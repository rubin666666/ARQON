# Правила роботи з проєктом ARQON

Головний пріоритет: економно використовуй контекст, токени та обчислення.

1. Не аналізуй весь проєкт без прямої необхідності.
2. Для кожної задачі спочатку визнач мінімальний набір файлів, які реально потрібні.
3. Не читай усі сторінки, компоненти та стилі «про всяк випадок».
4. Не скануй node_modules, .next, dist, build, coverage, cache та інші службові або згенеровані папки.
5. Не аналізуй public та медіафайли без прямої необхідності.
6. Не перечитуй файли, зміст яких уже є в поточному контексті, якщо вони не змінювались.
7. Не запускай повний аудит сайту без прямої команди.
8. Не запускай build, lint, tests або повний typecheck автоматично після кожної дрібної зміни.
9. Запускай перевірки тільки тоді, коли вони реально потрібні для поточної задачі.
10. Не роби додаткових покращень, рефакторингів або cleanup, яких користувач не просив.
11. Не змінюй сусідні частини сайту, якщо вони не пов'язані з задачею.
12. Зберігай існуючий дизайн, структуру та архітектуру, якщо користувач прямо не просить їх змінити.
13. Для UI-задач працюй тільки з конкретною сторінкою, секцією або компонентом.
14. Для багів шукай причину найкоротшим шляхом, а не через аналіз усього репозиторію.
15. Якщо відомі конкретні файли, працюй спочатку тільки з ними.
16. Якщо потрібен додатковий файл, відкривай лише той, що безпосередньо пов'язаний з поточною задачею.
17. Не створюй довгі плани для простих задач. Якщо рішення очевидне, одразу внось зміни.
18. Не витрачай час на довгі пояснення після виконання. Коротко напиши, що було змінено.
19. Якщо задача занадто широка, не починай повний аналіз. Спочатку запропонуй розбити її на кілька менших задач.
20. Працюй так, щоб кожна задача мала мінімально можливу область змін.

Перед кожною дією став собі питання: «Чи справді мені потрібен цей файл, ця команда або ця перевірка для виконання поточної задачі?» Якщо ні — не використовуй їх.

Мета: максимальна якість результату при мінімальній витраті токенів, контексту та агентних циклів.
